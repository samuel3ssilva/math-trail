# Privacy

Math Trail is a tool for a **parent** to plan and reflect on off-screen play.
It is built around one principle: **data about a child never leaves the device,
and no data about any real child exists in this repository.**

## What data exists

| Data | Contents | Where it lives |
|---|---|---|
| Session logs | window, activity id, completion, mood, ease, reward, optional minutes, optional free-text note | `localStorage` on the parent's device only |
| Profile | a display name, birth month, current book chapter | `localStorage` on the parent's device only |
| Adaptive state | levels, mastery, mode flags — all derivable from the logs | `localStorage` on the parent's device only |
| Daily plan / active session / rest days | ephemeral operational state | `localStorage` on the parent's device only |
| Exports | a JSON file the parent explicitly downloads | wherever the parent saves it |

## What is never collected

- No accounts, no sign-in, no server, no database.
- **No analytics of any kind** — no page views, no telemetry, no crash reporting.
- **Zero third-party requests at runtime.** Typography uses system font
  stacks; every request the app makes is same-origin.
- No camera, no microphone, no voice recognition, no location.
- No calls to AI/LLM services. The "adaptive engine" is local, rule-based code.
- Nothing about the child is transmitted anywhere, ever.

## Purpose limitation

Data is used exclusively to (1) suggest the next activity, (2) show progress to
the parent, and (3) power the safety rules (story mode, cooldowns). Nothing else.

## Deletion, export, retention

- **Export:** Settings → "Export JSON" produces a complete portable backup.
- **Delete:** Settings → "Delete all sessions" wipes logs and derived state.
  Browser-level "clear site data" removes everything, including the profile.
- **Retention:** there is no server-side retention because there is no server.
  Data lives until the parent deletes it.

## Real data vs. synthetic data — the hard boundary

- The public repository contains **only synthetic data**, generated by
  [`scripts/generate-demo.mjs`](../scripts/generate-demo.mjs) with a fixed seed,
  or hand-written fixtures marked `"_synthetic": true`.
- The automated privacy guard ([`tests/privacy.test.mjs`](../tests/privacy.test.mjs))
  fails CI if personal identifiers, real birth dates, personal storage-key names
  or private directories ever appear in tracked files or in the deploy artifact.
- Private folders (`private-local-data/`, `backups/`, `migration-input/`,
  `exports/`, `*-backup-*.json`) are blocked by `.gitignore` and asserted
  untracked by the same test.
- The code contains **no storage keys derived from a person's name**. Migration
  from older personal installations happens through the standard export/import
  flow, on the owner's device.

## Threats and limits

See [threat-model.md](threat-model.md). The honest residual risks: anyone with
access to the unlocked device browser profile can read the data; and free-text
notes are under the parent's control — the UI encourages neutral phrasing, but
cannot prevent sensitive text from being typed.
